Pause change tracking

This stops Trignis reading and exporting changes for . It does not stop the source database recording them.

  • Downstream systems stop receiving data. But beware, nothing will report an error.
  • The processed version stops advancing, so the backlog grows for as long as this lasts.
  • On SQL Server, a pause longer than CHANGE_RETENTION ages the backlog out and forces a full resync.
  • On PostgreSQL, the outbox table keeps growing and cannot be trimmed past the stored version.
  • The pause survives restarts and config reloads. It only ends when someone resumes it here.
